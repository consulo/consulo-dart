# Consulo port

This repository is a fork of [flutter/dart-intellij-third-party](https://github.com/flutter/dart-intellij-third-party)
ported to Consulo. Upstream history is kept, upstream files stay at their original paths, so upstream changes can be merged.

## Layout

- `third_party/pom.xml` - the Consulo plugin (Maven). `third_party/thirdPartySrc/analysisServer` is an extra source root,
  as in upstream `build.gradle.kts`. Upstream `gen/` is not used: lexers and parsers are generated by maven-consulo-plugin
  (`*.flex.idea` markers select the IntelliJ lexer skeleton, so upstream `.flex` files are used as is).
- `third_party/src/main/java/consulo/dart` - Consulo-only code (module extension, SDK type, notification groups, ...).
- `third_party/src/main/java/consulo/dart/compat` - IntelliJ platform APIs without a public Consulo equivalent,
  ported from intellij-community with their original names.
- `tool/consulo/sync_upstream_resources.py` - regenerates `LOCALIZE-LIB` (from `messages/*.properties`, used by `DartBundle`)
  and `ICON-LIB` (from `icons/*.svg`, used by `icons.DartIcons`). Run after merging upstream.

## Decisions

- Java only: upstream Kotlin files are converted to Java, keeping the API Kotlin generates
  (`XxxKt` classes for top-level functions, `INSTANCE` for objects, `getX()` for properties).
- LSP is not supported: LSP sources are renamed to `.java_` / `.kt_` (kept for merges), `DartConfigurable` LSP checks return false.
  The `hints` inlay providers and `DartClosingLabelManager` only work with LSP and are disabled the same way.
- Analytics is dropped; the analysis server is started with `--suppress-analytics`.
- Dart SDK is a Consulo SDK (`DartSdkType`), Dart support is enabled per module by `DartModuleExtension`.
  Upstream `DartSdk` / `DartSdkLibUtil` keep their public methods but are implemented on top of that.
- The classic analysis server protocol is kept; the plugin's own PSI based features are the main path.
- `org.jetbrains.annotations` nullability annotations of upstream are kept as is.
- Internal Consulo APIs (`*.internal.*` packages) are not used.

## Missing Consulo APIs

Places where upstream needs a platform API Consulo does not provide publicly; worked around in the plugin for now:

- `PostfixTemplateProvider.getTemplates()` is final and computed once; upstream `DartPostfixTemplateProvider` fills templates from the analysis server later.
- `ExtendableTextField` is in desktop-awt-ui-impl only; `BasicComboBoxWithBrowseButton` places a browse button inside the editor field instead.
- `StopProcessAction` (ide-impl) has no `setProcessHandler`; upstream reuses one action for reruns.
- `ResolveCache.clearCache(boolean)`; `PsiManager.dropResolveCaches()` is used.
- `TemplateBuilderImpl.replaceRange(range, var, expression, alwaysStopAt)` is internal; `TemplateBuilder.replaceElement(file, range, ...)` is used.
- `FileOffsetsManager`, `ModalityUiUtil`, `ConstantNode.withLookupItems`, `PsiBuilderUtil.parseBlockLazy`, `FileBasedIndex.getSingleEntryIndexData`
  and a few utilities are ported to `consulo.dart.compat`.
- `XmlTypedHandlersAdditionalSupport` does not exist; `xml/DartXmlTypedHandlersAdditionalSupport` is disabled (`.java_`).
- `EnterHandlerDelegate.invokeInsideIndent` does not exist; the no-op overrides are dropped.
- `ColorSettingsPage.getIcon()` does not exist; the method is kept without `@Override`.
- `UpdateJavaScriptFileCopyright` does not exist; `UpdateDartFileCopyright` scans leading comments itself.
- `AllIcons.Nodes.Include` does not exist; extension completion items use the interface icon.
- `LanguageCodeStyleSettingsProvider.customizeDefaults` does not exist; defaults come from `getDefaultCommonSettings()`.
